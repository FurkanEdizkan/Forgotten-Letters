# design-sync notes — Forgotten Letters

## What this DS is
- The design system **is this repo** (`src/components/ui/*`), not a published/installed
  package. It's a Next.js app, so there is **no library `dist/` build and no `.d.ts` tree**.
- Shape: `package`, **synth-entry mode** (converter synthesizes an entry from `src/`).
- 9 components synced: Button, Card, Badge, Input, Textarea, Label, Skeleton, Avatar, Tabs.
  Compound sub-parts (CardHeader/Title/Description/Content/Footer, TabsList/Trigger/Content)
  are excluded from the card list via `componentSrcMap: null` but **remain in the bundle
  exports** (18 total) and are composed inside the Card/Tabs previews.

## Pre-converter setup (wired as `cfg.buildCmd` = `.design-sync/compile-css.sh`)
The script (re-run automatically each sync) does three things:
1. Creates `.ds-sync/pkgroot/` — a clean package root (package.json + a `src` symlink,
   **no nested node_modules**) and points `node_modules/forgotten-letters` at it. A direct
   self-symlink to the repo root makes ts-morph's `.d.ts` scan loop forever (ELOOP) — don't.
2. Symlinks `node_modules/forgotten-letters -> .ds-sync/pkgroot`.
3. Compiles Tailwind v4 (`src/app/globals.css` + `@theme` tokens + all app utility classes)
   with `@tailwindcss/cli` into `.ds-sync/pkgroot/compiled.css`, prepending
   `.design-sync/fonts-header.css`. `cfg.cssEntry: "compiled.css"` (resolved relative to
   PKG_DIR = pkgroot; it must live INSIDE pkgroot or the converter rejects it as outside).

## Props (`.d.ts`)
- Synth mode can't extract real prop types → all `<Name>Props` are **hand-written in
  `cfg.dtsPropsFor`**. **If a component's real API changes in `src/`, update `dtsPropsFor`
  by hand — it will NOT auto-update.**

## Styling / fonts
- Dark-only DS. Preview `.tsx` wrap each story in a `var(--color-bg)` stage so components
  render on their intended dark field (the preview scaffold hardcodes a white body).
- **Preview-only sizing uses inline styles, never new Tailwind classes** — the compiled CSS
  only contains classes actually used in the app's `src/`, so a novel utility class in a
  preview would not be styled.
- Brand fonts (Inter/Cinzel/JetBrains Mono) are injected by Next at runtime in the real app.
  For the DS they're defined in `.design-sync/fonts-header.css` via a Google Fonts remote
  `@import` → validate reports `[FONT_REMOTE]` (non-blocking, expected). If the remote is
  blocked at render time, text falls back to Arial Narrow / system-ui / ui-monospace.

## Render check
- Chromium build 1228 is cached under `~/.cache/ms-playwright`; `playwright` was installed
  into `.ds-sync` with `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` and launches the cached binary
  automatically (no `DS_CHROMIUM_PATH` needed).

## Re-sync risks (watch-list)
- **`cfg.dtsPropsFor` is hand-maintained.** Component API drift in `src/` silently rots the
  props docs the design agent codes against. Re-check the 9 bodies against source on re-sync.
- **Fonts depend on a remote Google Fonts `@import`.** No local `@font-face`/woff2 ships. If
  Claude Design ever blocks remote fonts, wire `cfg.extraFonts` with self-hosted woff2 instead.
- **CSS is regenerated by `buildCmd` every run.** New utility classes in components are picked
  up automatically (Tailwind scans `src/`); `@theme` token changes flow through too. Just
  always let `buildCmd` run before the converter.
- Machine-state symlinks (`node_modules/forgotten-letters`, `.ds-sync/pkgroot`) are recreated
  by `buildCmd`; harmless as long as `npm install` has populated `node_modules` first.

## Known render warns
- `[FONT_REMOTE]` for "Inter", "Cinzel", "JetBrains Mono" — expected (see above).
- Palette is grimdark (blood primary #8B1A1A, tarnished gold accent #B8923F, Cinzel display).
  Button `danger` variant uses `--color-danger` (flare red), not `--color-accent` (gold).
