## Features

### First start: migrations, backup, the first owner (`first_start`)

**A group installs the app and becomes its owner without editing passwords into files.**

1. hooks → backupService: dump before migrating
2. hooks → infra: apply migrations under a lock
3. hooks → setupService: no owner: log a setup link
4. visitor → publicPages: opens /setup/<token>, chooses username and password
5. publicPages → setupService: create the first owner
6. setupService → repos: insert owner, use the token
7. setupService → authService: start a session

### Invite and join (`invite_and_join`)

**Nobody registers alone: an owner or admin sends a link that fixes the role.**

1. admin → areas: create an invite (role, note)
2. areas → inviteService: create
3. inviteService → repos: insert invite
4. inviteService → auditService: record invite
5. visitor → publicPages: opens /invite/<token>, chooses username and password
6. publicPages → inviteService: accept
7. inviteService → repos: lock invite, insert user, mark used
8. inviteService → authService: start a session

### Managing people (`managing_people`)

**The owner keeps the group's accounts in order without email.**

1. owner → areas: change role, disable, reset, anonymise
2. areas → peopleService: apply
3. peopleService → repos: update user (version checked)
4. peopleService → authService: end sessions
5. peopleService → auditService: record change

### Failure and recovery (`failure_and_recovery`)

**A group without an ops person can see what is wrong and get back on its feet.**

1. owner → health: checks /health/ready
2. health → infra: ping the database, migrations applied
3. owner → areas: download or restore a backup
4. areas → backupService: dump or restore
5. backupService → infra: pg_dump, pg_restore

### Sessions and the account page (`sessions`)

**Everyone controls their own sign-in.**

1. user → hooks: any request with the cookie
2. hooks → authService: resolve session
3. authService → repos: read session, slide expiry
4. user → areas: change password, sign out everywhere
5. areas → authService: change password, end sessions

### Sign-in: one screen for every role (`sign_in`)

**Owners, admins and users sign in on the same screen and land in their own area.**

1. user → publicPages: username, password, remember me
2. publicPages → authService: signIn
3. authService → infra: rate limit
4. authService → repos: find user, create session
5. authService → auditService: record sign-in
6. publicPages → user: cookie, redirect to the role area
